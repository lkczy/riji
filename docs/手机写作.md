# 用手机写日记（不开发手机 App 的办法）

这个程序的数据格式是**一天一个纯文本 `.md` 文件**，而且解码是**刻意宽容**的。
所以手机端不需要这个程序——**任意一个能编辑文本的 App 就够了**，配上同步工具即可。

这份文档里的结论**都是实测出来的**（`test/fs_diary_store_test.dart` 里有对应的回归测试）。
凭印象写的话，下面至少有三条会是错的。

---

## 一、手机上你只需要「一个名字正确的空文件 + 正文」

**前置字段（`---` 包围的那段 YAML）不用写。** 实测：

| 手机写出来的样子 | 电脑端读到什么 |
|---|---|
| 完全没有任何前置字段 | 自动补 `id: legacy-20261011`，`created` 用文件的修改时间，正文一个字没少 |
| 正文以 `---` 开头（Markdown 分隔线） | **原样保留在正文里**，没被当成元数据解析掉 |
| CRLF 换行（Windows 风格） | 原样保留 |
| 带 UTF-8 BOM | 自动去掉，不会在正文里留下看不见的怪字符 |
| 空文件 / 只有空白 | 认成空条目（无害，但会在列表里占一行） |
| 带完整前置字段 | `id` / 时间 / `device` 全都用文件里的 |

**而且不写反而更好**：手机写的前置字段里 `device` 是手机那个编辑器的名字，
而让电脑端自动补的话，程序会按实际情况填。所以**只写正文是最省事也最准的**。

唯一的小差别：自动补的 `id` 是 `legacy-20261011` 这种形式，而不是 ULID。
**不影响使用**——一天只有一个文件，不存在身份冲突。

---

## 二、唯一必须记住的规则：文件要放在「年份」子目录里

```
✅  <日记根>\2026\2026-10-11.md
❌  <日记根>\2026-10-11.md
```

**文件名必须正好是 `YYYY-MM-DD.md`**，多一个字、少一位数字，程序都会**静默忽略**——
不会报错，你只会觉得"我写的那天怎么没出现"。这是这个办法里唯一危险的坑。

放错**文件夹**的实测后果（不是猜的）：

```
文件放在根目录，保存前：  1 条    文件: [2026-10-11.md]
在电脑上编辑过之后：      2 条    文件: [2026-10-11.md, 2026\2026-10-11.md]
                                  ↑ 同一天出现两条
```

原因：**读取**时会递归扫描整个日记根目录（所以根目录那份也认），
但**保存**时按规范路径写（`年份/文件名`）——于是同一天有了两份。

> 这个问题在程序里有待修复（见文末「已知未修」）。
> 在修好之前，**手机上必须放进年份文件夹**。

## 三、具体怎么搭

### 需要装的东西

| 装什么 | 装在哪 |
|---|---|
| Syncthing | 电脑 |
| Syncthing-Fork | 手机（Google Play 上叫 Syncthing-Fork） |
| 一个纯文本 / Markdown 编辑器 | 手机，见下面「编辑器的要求」 |

### 步骤

1. **电脑**：装 Syncthing，把日记根目录（例如 `D:\someone\MyData`）加为共享文件夹。

   ⚠️ **必须设置忽略规则**，否则两台设备会互相制造冲突文件、容量翻倍：

   ```
   .drafts/
   .history/
   .trash/
   *.tmp-*
   .index.sqlite
   ```

   完整列表见 `lib/core/diary_paths.dart` 里的 `syncIgnorePatterns`。

   **另外把编辑器自己建的文件夹也忽略掉。** 比如 Obsidian 会在仓库里建一个
   `.obsidian/`，里面是**每台设备各自的界面状态**（窗口布局、最近打开的文件）。
   同步它没有好处，只会制造冲突文件。其他编辑器也可能有自己的元数据目录。

   程序本身会跳过所有 `.` 开头的目录，所以这些文件夹不会污染日记列表——
   需要忽略是为了**别让同步工具去同步它们**。

2. **手机**：装 Syncthing-Fork，接受那个共享，
   **同步位置要选一个别的 App 也能访问的目录**（例如 `Documents/` 下）。

   ⚠️ 这条是关键：Android 11 以上，如果同步到某个 App 的私有目录，
   **别的编辑器读不到那些文件**。

3. **手机**：装编辑器，打开上一步的目录。

4. **写今天的日记**：进 `2026\` 目录 → 新建文件 → 命名 `2026-10-11.md` → 写正文。

5. **回到电脑**：Syncthing 自动同步过来，程序里就能看到。

### 编辑器的要求

| 要求 | 为什么 |
|---|---|
| 能**打开任意文件夹**（不只是自己的沙盒） | 要打开 Syncthing 同步过来的目录 |
| **纯文本**，不自作主张加格式 | 加粗写成 HTML 或富文本标记会污染文件 |
| **不会自动改文件名** | 文件名就是日期，改了程序认不出来 |
| 保存为 **UTF-8** | 默认基本都是；能设置更保险 |
| 最好能**按日期自动生成文件名和路径** | 这样「文件名必须正好是日期」那条规则就不用靠人记了 |

**如果编辑器支持「每日笔记 / 模板 + 日期变量」**（Obsidian 的内置「日记」插件就有这个），
那第 4 步可以变成"点一下，自动在正确位置生成正确名字的文件"——
这是最理想的形态，因为它消掉了唯一那个危险的手工步骤。

### 手机上放在哪个目录

**推荐：`内部存储/Documents/riji/`**（也就是 `/storage/emulated/0/Documents/riji`）

选它的理由是**这个位置同时满足三个工具**：

| 需要访问它的东西 | 为什么这个位置可以 |
|---|---|
| Syncthing-Fork | 公共目录，它能同步 |
| 编辑器（Obsidian 等） | 公共目录，系统的文件夹选择器能选到它 |
| 文件管理器 / 数据线 | 看得见、拷得出来 |

还有一条同样重要：**卸载任何 App 都不会删掉它**。
放在 App 私有目录里，卸载那个 App 就等于删掉日记。

#### 不要用这些位置

| 位置 | 为什么不行 |
|---|---|
| `Android/data/<应用名>/files/` | Android 11 以上**别的 App 读不到**：Syncthing 同步不了，编辑器也打不开 |
| 应用私有目录（`/data/data/...`） | 同上，而且卸载即删除 |
| `DCIM/`、`Pictures/` | 那是给照片视频的，会被相册索引 |

#### 几个注意点

- **手机上的路径和电脑上不需要一致。** `D:\someone\MyData` 和手机上的
  `Documents/riji` 可以是同一个同步文件夹的两端，两边的路径名毫无关系。
- **优先内部存储，不要用 SD 卡**：卡可以拔出来，路径会变，同步就断了。
- Syncthing-Fork 会要求「**所有文件访问权限**」，这是 Android 11 以上的必需步骤，
  要在系统设置里手动授予（设置 → 应用 → 特殊应用权限 → 所有文件访问权限）。
- Syncthing 会在同步文件夹里放几个 `.st` 开头的文件（`.stfolder` 等），
  那是它自己的机制，不用管——程序会跳过所有 `.` 开头的目录。

#### 一件值得自己确认的事

公共目录有可能被**手机厂商的云服务**自动备份（有些云会连 `Documents/` 一起备份）。
日记是**明文**的（程序不做加密，你也明确不需要）——如果它被自动传到了云上，
那个假设就不成立了。这件事我没法替你查，得看手机云备份的设置里有没有包含这个目录。

### 手机端设置清单（照这个顺序做）

1. 装 `Syncthing-Fork` APK（**arm64** 版；2016 年以前的老手机才用 `armeabi-v7a`）

2. **把权限给全。** 这一步漏了会表现为「同步莫名其妙就不动了」：

   | 权限 | 去哪儿给 |
   |---|---|
   | **所有文件访问权限** | 设置 → 应用 → 特殊应用权限 → 所有文件访问权限 |
   | 通知 | 设置 → 应用 → Syncthing-Fork → 通知 |
   | **电池不受限制** | 设置 → 电池 → 电池优化 → 找到它 → 选「不优化」 |
   | 自启动（国产 ROM 才有） | 设置里搜「自启动管理」或「后台运行管理」 |

3. **配对设备**：两台互换设备 ID。电脑端的在管理界面「操作 → 显示 ID」，
   那一页还有个**二维码可以直接扫**，比手打 63 个字符省事。

4. **在电脑端把文件夹共享给手机**：文件夹 → 编辑 → 共享 → 勾上手机。
   （新建文件夹时默认没有共享给任何设备，这一步不能忘。）

5. **手机端添加文件夹**：

   | 字段 | 填什么 |
   |---|---|
   | 文件夹 ID | **`mydiary`** —— 必须和电脑端一字不差 |
   | 路径 | `Documents/riji` |
   | 类型 | sendreceive |

6. **在手机端也配一份忽略规则。** 每台设备各自一份、**不会互相同步**，
   所以电脑端配过不代表手机端配过了：

   ```
   .drafts
   .history
   .trash
   .obsidian
   *.tmp-*
   .index.sqlite
   ```

### 什么时候会同步

两台设备**在同一个 Wi-Fi 下就能直连同步**（局域网发现），不需要外网。

Syncthing 的全球发现服务器和中继都在国外，在国内可能连不上。
**但这对你的用法没影响**：在外面用手机写，回家连上 Wi-Fi 就自动同步。

如果需要「在外面用流量也能同步」，要额外做事：给电脑做端口转发、
或者两台设备连到同一个 VPN。不是必需的。

## 四、你会失去什么

| 失去 | 说明 |
|---|---|
| 每日一问、时光机 | 手机上就是纯编辑器 |
| 农历、黄历、字体调节、格式按钮 | 手机上都没有 |
| 全文搜索 | 手机编辑器只有文件级搜索 |
| 心情 / 天气 / 标签的**界面** | 但可以手写进前置字段，见下 |

### 想要心情和标签：手写前置字段

编辑器就是普通文本，所以直接写就行：

```markdown
---
mood: 平静
tags:
  - 工作
---
今天在外面，用手机写的。
```

程序会**原样保留**未知或已认识的字段，并在你第一次在电脑上编辑那天时补全
`id`、`created`、`updated`、`device`。字段的完整说明见 [DATA-FORMAT.md](DATA-FORMAT.md)。

## 五、出问题怎么排查

| 现象 | 先查什么 |
|---|---|
| 手机上写的日记在电脑上看不到 | ① 文件名是不是**正好** `YYYY-MM-DD.md`（最常见）② 是不是放在 `年份\` 目录里 ③ Syncthing 同步完成了吗 |
| 同一天出现两条 | 文件放错了文件夹（见第二节）。去日记目录看，把根目录那份挪进年份文件夹 |
| 电脑上出现 `xxx.conflict-...md` | 两台设备在同一天都改过。程序**两边都没丢**，把对方那份另存了。打开冲突文件手工合并 |
| 手机上出现 `.conflict-` 文件 | 同上，只是这次是手机端先收到的 |
| 同步很慢或反复同步 | 忽略规则没配全（见第三节），`.history/` 和 `.trash/` 必须忽略 |
| 程序里显示「N 个冲突」 | 两台设备改了同一天。见下面「冲突是怎么产生的、怎么处理」 |

### 冲突是怎么产生的、怎么处理

**程序会自动重新载入，但不会替你合并。** 它每 3 秒看一次当前这一天的文件
有没有被外部改过：

| 你的状态 | 程序的做法 |
|---|---|
| **没有未保存的内容** | 自动重新载入，并显示一条信息提示 |
| **有未保存的内容** | 什么都不做，等保存时生成冲突文件，**两个版本都留** |

自动重新载入的前提就是"没有未保存的内容"，所以**它不会丢掉你正在写的东西**。
这条边界有测试盯着（故意去掉保护，测试会失败）。

真正产生两个版本时，列表底部会出现「**N 个冲突**」，编辑区顶上会出现红色条。

冲突文件有两种来源，程序两种都认：

| 文件名的样子 | 谁生成的 |
|---|---|
| `xxx.sync-conflict-日期-时间-设备.md` | **Syncthing** 发现两台设备改了同一天 |
| `xxx.conflict-日期-时间-设备.md` | **本程序**在保存时发现磁盘被别处改过 |

处理办法都一样：两个文件都打开对比，把要留的内容合并进正式文件，删掉冲突文件。

### 让冲突变少的三个办法

**没有任何办法让它完全不可能**——两台设备各自编辑文件、后台同步，
这本质上就是分布式编辑的冲突问题。但可以大幅降低频率：

1. **首次同步完成前不要在手机上写。** 否则手机为某一天新建一份，
   而电脑上已经有那一天 → 必冲突。
2. **在电脑上动手之前，先让同步跑完。** 只要电脑先拿到手机的最新版，
   程序读到的就是新内容，不会撞车。
3. **同一天尽量只在一台设备上写。**「在外用手机写一半，回家在电脑上接着写
   同一天」是最容易撞车的做法。

> ⚠️ **不要**把电脑端设成 Syncthing 的「仅发送」(sendonly) 来躲冲突：
> 那会让电脑的版本**覆盖**手机的改动，**手机上写的日记直接消失**。
> 双向写日记只能用 `sendreceive`。

## 六、这条路的价值不只是省事

它顺带验证掉了**将来真做手机 App 时最容易翻车的三件事**：

| 验证项 | 状态 |
|---|---|
| 别的工具写的文件，电脑端读得对不对 | ✅ 已实测（第一节那张表） |
| 同步产生的冲突，程序处理得对不对 | 用起来就知道 |
| 忽略规则有没有真的生效 | 用起来就知道 |

这三件事恰恰是手机 App 的地基。所以哪怕之后还是决定写 App，这一步也没白做。

## 七、已知未修的问题

1. **文件放错文件夹会产生同一天两份**（第二节）。
   建议的修法：程序发现日记文件不在规范位置时，**把它挪到 `年份/` 下**，
   而不是另写一份。这样手机端放哪都行，容错大很多。
   代价是程序会移动用户的文件（在日记根目录内部、内容不变）。

2. ~~**备份还没做**~~ —— **已经做好了**。关程序时自动做一份（一天至多一份，
   自动快照只保留最近 30 份；手动快照永不删除），恢复只落到新文件夹。
   做法和取舍见 [`详细说明.md`](详细说明.md) 的「备份」一节。

   ⚠️ 但有一件事仍然只能你自己把握：**备份位置如果和日记在同一个盘，它挡不住盘坏**。
   真正防住盘坏的是"把备份传到云盘"那一步，而程序看不见云盘——
   **上传的节奏就是你的数据安全窗口**。

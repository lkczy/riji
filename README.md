# 日迹

一个本地优先的个人日记程序。**日记就是磁盘上的 Markdown 文件**，这个程序只是它更好用的入口。

- 数据格式规范见 [`docs/DATA-FORMAT.md`](docs/DATA-FORMAT.md) —— 那是全项目唯一不可逆的部分，优先于一切实现细节。
- 用手机写日记（不开发手机 App 的办法）见 [`docs/手机写作.md`](docs/手机写作.md) —— 里面的结论都是实测出来的。
- 备份：关程序时自动做一次（**一天至多一份**，自动快照只保留最近 30 份；手动快照永不删除）。备份位置要你自己设——**和日记在同一个盘时挡不住盘坏**，界面会如实告诉你这一点。
- 当前状态：Windows 桌面版可用，489 个测试覆盖。手机端**未开始**（`docs/手机写作.md` 里有一条零开发的替代路线，已实测可用）。

## 怎么启动

**双击项目根目录里的 `riji.lnk` 即可**（或者用 `riji.bat`，两者等效）。

### 为什么不是一个单独的 exe

Flutter 的 Windows 程序**不是一个文件，而是一个文件夹**：

```
build\windows\x64\runner\Release\
├── riji.exe          88 KB    ← 只是个外壳，单独挪走打不开
├── flutter_windows.dll   20 MB    ← 渲染引擎，必须同目录
└── data\                 7 MB     ← 编译后的 Dart 代码 + 资源，必须同目录
```

所以**不能把 exe 单独拷到浅一点的地方**。要在浅位置双击启动，只有两条路：

| 做法 | 说明 |
|---|---|
| **启动器**（当前用的） | 根目录放 `riji.lnk` / `riji.bat` 指向真正的 exe。不复制文件，永远启动最新构建 |
| **复制整个文件夹** | 把上面 4 项一起拷到别处（如 `D:\Apps\riji\`）。占额外 29MB，且每次重新构建后都要再拷一次 |

`riji.lnk` 由 `tool\build_release.ps1` 在每次构建后自动重新生成，所以不会指向旧位置。
`riji.bat` 是纯文本、用相对路径（`%~dp0`），跟着项目文件夹搬到哪都能用。

## 现在能做什么

| 功能 | 说明 |
|---|---|
| 打开即写 | 启动后光标直接落在今天的正文里，不用先点输入框 |
| 自动保存 | 停止输入 0.9 秒后落盘，状态栏明确显示「未保存 / 正在保存 / 已保存 / 失败」 |
| 草稿保护 | 编辑期间每 2 秒写一份草稿。**是节流不是防抖**，连写十分钟也一直有保护 |
| 草稿恢复 | 崩溃或强退后重启，若草稿比正式文件新，会问你要不要恢复 |
| 原子写入 | 先写临时文件再 rename，断电不会产生半截文件 |
| 日期导航 | 前一天 / 后一天 / 今天 / 日历选日期 |
| 全文搜索 | 内存全量扫描，正文、标签、心情、天气、日期都能搜 |
| 筛选 | 按标签 / 心情 / 天气筛选（「与」关系），条件会一直显示在左侧，一键清除 |
| 标签自动补全 | 输入时补全已用过的标签，常用的排前面；已经加在这一天的不会重复提示 |
| **写入前检查外部改动** | 保存前先确认「磁盘上的内容还是我读到的那一份吗」；不是的话把对方另存为冲突文件并明确提示，**绝不静默覆盖** |
| 每日一问 | 还没动笔时给一个写作引子。**120 条、12 个角度**，同一天稳定不变，可点「换一个」 |
| 时光机 | 随机翻到一篇以前写过的日记（只挑正文非空的），可以连着「再翻一篇」 |
| 字体与行距 | 字号 / 行距 / 字重 / 行宽四项，即时生效、随改随存。入口在「外观」菜单里 |
| 内联格式 | 加粗 / 斜体 / 下划线，选中文字点按钮或按 Ctrl+B / Ctrl+I / Ctrl+U。**插入的是 Markdown 标记，不是富文本属性** |
| 心情、天气、标签 | front matter 里的结构化字段，可搜索可统计。**心情和天气都是「预设 + 自由输入」**——预设三秒钟点完，自由输入保证想写的东西写得下 |
| 往年的今天 | 自动列出同月同日的历史日记 |
| 同步冲突提示 | 识别 Syncthing 和自身产生的冲突文件，**绝不自动合并** |
| **历史版本** | 打开一天时、以及编辑过程中每隔一段时间自动留一份快照，可查看、可恢复。恢复前会先把当前内容留一份 |
| **删除与回收站** | 删除是软删除（移进 `.trash`，不抹字节），回收站里能看、能恢复、能永久删除。那一天已有新内容时恢复不会覆盖，而是另存为冲突文件 |
| **单实例锁** | 用操作系统级文件锁保证只有一个实例在写日记目录，避免两个窗口互相制造冲突文件 |
| **黄历悬浮卡片** | 鼠标停在某一栏约 0.65 秒（或长按）弹出当天的干支、冲煞、宜忌。**宜忌没有唯一正确答案，卡片上明确标注它是传统历注** |
| 一键导出 | 在编辑区右下角的「更多」菜单里，导出成单个 Markdown 文件 |
| 专注模式 | 隐藏左侧列表，全屏写作 |
| 深色模式 | 跟随系统 / 浅色 / 深色三选一，在标题栏的外观菜单里切换，选择会被记住 |
| 更改日记位置 | 在编辑区右下角的「更多」菜单里（菜单项叫「**日记存储位置**」）。切换前会实测新位置能否写入、里面已有什么；可以把现有日记**复制**过去（只复制，从不移动） |

## 写入保护：绝不静默覆盖

这是这个程序里最要紧的一条行为。触发场景都是「本地优先 + 多端同步」必然出现的：

- Syncthing 从手机同步过来一段话，你同时在电脑上继续编辑
- 程序开了两个窗口，一个窗口的改动被另一个抹掉
- 你用 VS Code / 记事本改了当天的 `.md`，程序没有重新读

**做法**：存储层记住「每个文件我上次读到的原始内容」。保存前重新读一次磁盘，
如果发现内容已经变了，就**两个版本都保留**：

| 版本 | 去向 |
|---|---|
| 对方的（磁盘上现有的） | 原样另存为 `YYYY-MM-DD.conflict-<时间>-<设备>.md` |
| 你的（正在编辑的） | 正常写入正式文件 |

然后在界面顶部顶出一条**不会自动消失**的警告条，告诉你冲突文件在哪、去合并。

不做的事：不自动合并（程序无法判断你想留哪句话）、不覆盖对方、不把提示做成
几秒后消失的 toast（那等于把冲突埋起来，和静默覆盖只差一步）。

### 单实例锁

上面第二条（「程序开了两个窗口」）其实**不该发生**，所以现在直接堵住：

| 做法 | 为什么不用另一个做法 |
|---|---|
| 用一个**操作系统级的文件锁**（`FileLock.exclusive`）锁住 `%APPDATA%\riji\instance.lock` | 自己维护一个带 PID 的锁文件，就得判断「那个进程还活着吗」。这个判断本身会出错（PID 会被复用），最后表现成「程序说你已经开了一个，其实没有」，而用户只能手工去删文件 |
| 锁文件放**设置目录**，不放日记目录 | 单实例是「每台机器」的概念，而日记目录是可配置、会被同步到别的设备的 |
| 拿不到锁就显示一个说明页，不启动日记界面 | 第二个实例仍然会开一个窗口（不用插件没法把已开那个窗口调到前台），但它**完全不碰日记目录**——一行设置都不读 |

进程崩溃、被任务管理器杀掉、断电时，操作系统会自动释放这个锁，不会留下
需要手工清理的残留。跨进程验证过：程序运行时，另一个进程尝试加锁会失败。

## 每日一问与时光机

### 每日一问

**还没动笔时**（正文、心情、天气、标签全空）在编辑区上方给一个写作引子，
一开始写就自动消失——空页面才是障碍，有内容之后就不是了。

120 条引子，**12 个角度**各 10 条：今天发生了什么 / 感受 / 人 / 观察与细节 /
身体 / 思考与反思 / 工作与学习 / 感恩与小确幸 / 想象与假设 / 未来与计划 /
换位与对话 / 随想与碎片。多角度是有意的——同一个问题再深刻，天天问也会失效，
换一个角度往往才能让人想起今天真正值得记的那件事。

三条刻意保证的性质（都有测试守着）：

| 性质 | 为什么 |
|---|---|
| **同一天永远是同一条** | 做成随机的话，切走再回来就换成别的了，用户会怀疑自己记错 |
| **相邻日期一定在不同角度上** | 否则会连着十天都在问同一类问题，一样没话说 |
| **任意连续 120 天刚好覆盖全部 120 条** | 靠「步长与总数互质」这条数论性质，不重不漏 |

「换一个」改变的是相位而非步长，相位步长同样与总数互质，
所以换满一圈刚好遍历全部引子，不会反复撞同几条。

**引子不写进日记文件**：它是写作的脚手架，不是日记的内容。
（想要的话可以自己把问题抄进正文。）

### 时光机

编辑区右上角的骰子图标。随机翻到一篇以前写过的日记，跳完给一条可
「再翻一篇」的提示。

只挑**正文非空**的条目——翻到空白的一天毫无意义，反而让人以为日记丢了。
也不会连续翻到同一条（否则观感像"点了一下没反应"）。

## 字体与格式

这两件事经常被混在一起，但它们完全不同，风险也完全不同。

### 编辑器排版（字号 / 行距 / 字重 / 行宽）

入口：标题栏的**「外观」菜单 → 字体与行距**（和主题放在一起，因为都是"看着舒服"这一类）。

改动**即时生效、随改随存**，没有「应用/取消」——这类"看着调"的设置，反馈回路越短越好。
想退回去点「恢复默认」。

| 项 | 范围 | 默认 |
|---|---|---|
| 字号 | 13–28 px | 16 |
| 行距 | 1.3–2.8 倍 | 1.9 |
| 字重 | 常规 / 中等 / 加粗 | 常规 |
| 行宽 | 520–1100 px | 760 |

**这些设置永远不写进日记文件。** 正文是纯文本，换台机器、换个程序打开，内容一模一样；
排版是各人看着舒服就好的事，不该跟着文件跑，也不该在同步时互相覆盖。
设置读进来时每个值都会**夹回合法范围**——设置文件被改坏不该让正文变成 0 号字。

### 内联格式（加粗 / 斜体 / 下划线）

编辑区上方有一排格式按钮，也支持快捷键：

| 操作 | 快捷键 | 写进文件的样子 |
|---|---|---|
| 加粗 | `Ctrl+B` | `**文字**` |
| 斜体 | `Ctrl+I` | `*文字*` |
| 下划线 | `Ctrl+U` | `<u>文字</u>` |

**这里做的是插入 Markdown 标记，不是改某个加粗属性。** 原因：富文本意味着正文要存成
带格式的数据结构，而 Markdown 源码本身就是最好的格式——几十年后还能读、能 grep、
能 diff、能用任何编辑器打开。代价是源码里能看到标记符号，换来的是文件永远是纯文本。

几个刻意的行为：

- **再按一次取消格式**（标记在选区里、或紧贴选区两侧，两种都能识别）
- **斜体不会把粗体拆坏**：在 `**粗体**` 里选中文字按斜体，会再包一层变成 `***文字***`，
  而不是拆出一个残缺的 `*文字*`
- **光标没选中东西时**，插入一对空标记并把光标放在**两个标记之间**（不是选中整对标记，
  否则一打字就把标记全替掉了，格式反而没了）

**关于下划线**：Markdown 没有原生的下划线语法（`_` 是斜体的另一种写法）。
这里用 `<u></u>` 内联 HTML，是 CommonMark 允许的写法，但**不是所有 Markdown 渲染器都认**，
而且在源码里比 `**` 更显眼。如果只是想做强调，建议用粗体代替。

## 农历、节日与节气

左侧日期列表的每一行，按下面的位置显示这一天的时间信息：

```
2026-10-01 周四 国庆节              平静     阳历节日在日期后面
八月廿一                                     普通日子只有农历
把日记程序的数据格式定下来了。

2026-02-17 周二                    平静
春节 · 正月初一                              阴历节日在农历日期前面
过年了。

2026-02-18 周三                    平静
正月初二 · 雨水                              节气在农历日期后面
雨水的节气到了。

2027-08-08 周日                    平静
七夕 · 七月初七 · 立秋                       第二行三段齐全时的顺序
2031-10-01 周三 国庆节             平静
中秋节 · 八月十五                            同一天既是阳历节日又是阴历节日
```

| 内容 | 位置 |
|---|---|
| 阳历节日 | 跟在**阳历日期**后面（第一行） |
| 阴历节日 | 排在**农历日期**前面（第二行） |
| 二十四节气 | 排在**农历日期**后面（第二行） |

阳历节日和阴历节日在数据层就是**两个独立字段**，因为在界面上它们要出现在两个不同位置。
两者可能撞在同一天——1950–2100 这 151 年里就有 **45 天**是这样，比如
**2031-10-01 是国庆节 + 中秋节**、1982-10-01 也是，2033-02-14 是情人节 + 元宵节。
所以不能合并成一个字段，否则会丢掉一个。有测试扫过全部 151 年找出这种重合的日子，
确认两边都保留、且分别落在两行上。

颜色也有区分：节日用主色加粗（最显眼），农历日期最淡，节气用第三个颜色和节日分开。
第二行用 `Text.rich` 拼成一行，窄侧栏下整体省略号收尾，不会溢出。

包含的内容：

| 类别 | 举例 |
|---|---|
| 农历日期 | `正月初一`、`闰六月十三`、`腊月廿七` |
| 公历节日 | 元旦、情人节、妇女节、劳动节、儿童节、国庆节、圣诞夜…… |
| 按星期算的 | 母亲节（5 月第二个星期日）、父亲节、感恩节 |
| 农历节日 | 春节、元宵节、端午节、七夕、中秋节、重阳节、腊八节、除夕 |
| 二十四节气 | 立春、清明、夏至、霜降、冬至…… |

**除夕不是写死的「腊月三十」**：腊月有时 29 天有时 30 天，所以是按
「第二天是正月初一」判定的。闰月里的同名日子也不算农历节日
（闰五月初五不是端午）——这条有测试扫过全部 151 年。

### 为什么是查表而不是推算

农历要算朔望月，节气要算太阳黄经，两者都是**天文推算**。用低精度公式在个别年份
会差一天，而日记里显示错日期比不显示更糟。所以数据是生成的，并且经过交叉验证：

| 项目 | 结果 |
|---|---|
| 数据范围 | 公历 1950–2100（表里多存 1949 和 2101 两个农历年，用来夹边界） |
| 交叉验证 | 和 .NET 的 `ChineseLunisolarCalendar` **逐日对拍 55544 天** |
| 一致 | 只有 60 天不一致，集中在 2089 和 2097 各一处月首边界 |
| 那 60 天的裁决 | 另有三个独立实现（lunar_python / cnlunar / zhdate）与 .NET 意见相反，**3 比 1**，所以采用了多数派 |

范围外一律返回 `null`，界面就是空的——**宁可什么都不显示，也不显示错的**。

复现验证：

```powershell
# 生成数据表（需要 pip install lunar_python）
python tool\generate_chinese_calendar.py --emit-dart lib\core\chinese_calendar_data.dart --emit-fixture test\chinese_calendar_fixture.dart

# 和 .NET 逐日对拍
powershell -File tool\verify_lunar_against_dotnet.ps1
```

解码这部分（拆位段、从正月初一往前走）由 `test/chinese_calendar_fixture.dart` 里的
357 个边界日期守着：每个农历年的正月初一、每个闰月的初一、每一年的除夕。

## 右下角的「更多」菜单

编辑区右下角（也就是窗口右下角）有一个 `⋮` 按钮，日记的"非写作"操作都收在这里：

| 菜单项 | 做什么 |
|---|---|
| 打开日记文件夹 | 在资源管理器里定位到日记目录 |
| 日记存储位置 | 改日记存哪（见下面的「更改日记位置」） |
| 导出 | 导出成单个 Markdown 文件 |
| 备份 | 立刻做一份备份（见下面的「备份」）。预览模式下这一项整个不出现 |
| 历史版本 | 查看 / 恢复历史快照 |
| 回收站 | 查看 / 恢复 / 永久删除已删除的日记 |
| 删除这一天的日记 | 软删除当前这一天；这一天还没写过时置灰 |

顺序是刻意的：**日常操作在上，数据管理在中，破坏性的单独隔在下**。删除项在
没写过东西时是**置灰而不是隐藏**——隐藏会让人以为没这个功能。

> **关于「…」**：菜单项后面**不带**「…」，而对话框内部的按钮（比如
> 「设置备份位置…」「从备份恢复…」）**保留**它。理由：这个菜单里每一项都会
> 打开对话框或确认框，有的带有的不带反而不一致，所以菜单统一去掉；
> 而对话框里的按钮确实会再弹一层，留着更准确。

> 收进菜单之前，「打开文件夹」和「导出」是常驻在状态栏上的两个按钮。
> 顺带修掉了一个真实的布局问题：状态栏当时用「`Spacer` + `Flexible`」分配空间，
> 两者各占一半自由空间，而 `Flexible` 是松约束——路径文字用不到那一半时，
> 多出来的空白**不会还回去**，于是 `⋮` 被留在了偏中间的位置
> （实测：窗口宽 1200，按钮中心停在 928 而不是贴到右边缘）。
> 现在路径改用 `Expanded` 吃掉剩余空间并右对齐，按钮才真正落在角上。
> 界面测试用**坐标**验证这一点，而不是只验证按钮存在。

## 历史版本与回收站

这两个是菜单里更"重"的功能，单独说明。

### 历史版本

**它挡的是哪一类损失**：备份挡的是"设备级"丢失（盘坏了、文件夹被误删，见「备份」），
历史版本挡的是"内容级"丢失——**已经落盘的内容被改掉了**。

在自动保存的程序里这一条格外重要，因为：

> 你在 Word 里可以「关闭而不保存」。这里没有这道闸门——文件在 900 毫秒内就提交了。

所以对已经存进去的内容，恢复途径只有两条：当前编辑会话里的 `Ctrl+Z`，
以及磁盘上留下的历史。前者重启就没了，后者是这个功能提供的。

**做这个功能时顺带修掉了一个会丢数据的 bug。** Flutter 的撤销栈记录 controller
的**每一次**值变化，不区分是用户敲的还是程序赋的；而本程序所有日期共用一个
controller，于是撤销栈里混着好几天的内容。实测后果是：**切到别的日期再切回来
按 `Ctrl+Z`，会把那一天的内容灌进当前这天，并在 900ms 后自动保存落盘**，
原内容没有任何副本。现在输入框子树会随正文版本重建（撤销栈跟着清空），
并且 `test/ui_test.dart` 里的「撤销不会跨日期」有回归测试守着——
那个测试在关掉修复之后确实会失败。

**什么时候留快照**（这里有个关键的设计约束）：

| 时机 | 原因 |
|---|---|
| **打开某一天时** | 这就是「我今天坐下来写之前，这篇是什么样」，整条历史里最有用的一份 |
| 编辑过程中距上次快照超过 **10 分钟** | 挡「写了半小时之后改坏」 |
| 点「留一份当前版本」 | 手动，不受时间限制 |
| **恢复历史版本之前** | 无条件留一份。没有它，「恢复」本身就会变成一次丢内容 |
| 内容与最新一份完全相同时 | **不留**。快照的价值在于记录另一个样子 |

> **快照的粒度必须比保存频率粗得多。** 自动保存是亚秒级的，如果按"每次保存前
> 留一份"来做，会得到一堆相隔一秒、彼此几乎相同的文件——看起来历史很丰富，
> 实际上没有一份有用，列表还会长到没法看。所以按**会话**和**时间网格**留，
> 而不是按保存次数。这也是为什么自动快照那条路径在绝大多数保存上
> 一个字节都不读：内存里记着"上次快照是什么时候"，十有八九一句话就返回了。

**存在哪**：`<日记根>/.history/2026-10-04/213045123-opened.md`。文件名自带
时刻和原因（`opened` / `auto` / `manual` / `before-restore`），所以**把文件
单独拷出来也自解释**。存的是**原始字节**而不是重新编码的结果——手工加过的
注释、程序还没认识的前置字段，都能原样恢复。

每天最多 30 份，超出时丢掉**第二份**（索引 0 那份是「打开时的样子」，最该保住）。

### 回收站

删除是**软删除**：文件被移到 `.trash`，内容一个字节都没少。回收站里能看、
能恢复、能永久删除（只有「永久删除」才真的抹字节，所以要二次确认）。

**恢复时如果那一天已经有内容了**（删完又写了新的），**绝不覆盖**：回收站里
那份会被另存为冲突文件，两边都保住，界面明确告诉你它去了哪。

删除会连带清掉那一天的草稿（否则下次启动会提示你恢复一篇已经删掉的日记），
但**保留历史快照**——那是这一天另一层独立的保护。

## 黄历悬浮卡片

**把鼠标停在左侧某一栏上约 0.65 秒**，右边会弹出一张这一天的黄历卡片；
**长按**同一栏也能弹出（手机上没有 hover，长按是唯一的入口，所以这个兜底不是可选项）。

卡片是**只读**的：包在 `IgnorePointer` 里，不会挡住底下的点击；鼠标移开或滚动列表就关掉。

### 这张卡片里有两类可信度完全不同的东西

这是这个功能最要紧的一点，所以界面上把它们分开显示：

| 内容 | 性质 | 能不能验证 |
|---|---|---|
| 干支（年/月/日）、冲煞 | **历法推算**，有唯一答案 | ✅ 能 |
| 宜、忌 | **择日学（传统历注）**，各家通书不同 | ❌ **不能** |

实测依据（同一天、两个独立实现）：

```
干支：lunar_python 与 cnlunar 在 730 天里 100.0% 一致（年/月/日三项都是）
宜忌：同一年里「完全一致的日子」是 0.0%
      「宜」条目交并比 10.3%、「忌」只有 3.9%
      2026-01-01 两天都列的只有「塞穴」「补垣」两个词
```

所以干支、冲煞是**可验证**的，而宜忌**没有唯一正确答案**——
它不是农历的一部分，是另一套体系。卡片上因此写着「宜忌是传统历注……
仅供参考，不是事实」，这一点不能省。

### 年干支用的是春节分界

`getYearInGanZhi()` 按**春节**分界（2026-02-05 已过立春、未到春节，仍是乙巳；
2026-02-18 才变丙午），和农历年一致，也和 cnlunar 的约定一致——所以它可被交叉验证。
另一派是**立春分界**（八字/命理用），两者在立春到春节之间那十几天会不同。
这里刻意选春节分界：它和界面上显示的农历年一致，不会出现「农历还写着腊月、
年干支却已经翻篇」的观感矛盾。

### 数据

| 项目 | 值 |
|---|---|
| 覆盖范围 | 公历 **2000–2060**（22281 天） |
| 文件 | `assets/huangli.tsv`，约 1.4 MB |
| 生成 | `tool/generate_huangli.py` |
| 插件 | **没有**。读取用 `rootBundle`，属于核心 Flutter |

范围外（比如 1990 年）**不显示卡片**——宁可没有，也不显示错的。

做成**资源文件而不是 Dart 源码**：两万多行的常量会让每次编译都变慢，
而资源文件是独立文件、不参与编译。

每一行是一天，从起始日**连续**排下来，所以不需要在数据里存日期：

```
年干支 \t 月干支 \t 日干支 \t 冲(地支) \t 煞(方位) \t 宜索引串 \t 忌索引串
```

宜忌用**两位 36 进制索引**指向词表（114 个词，写在 `lib/core/huangli_data.dart`）。
词表按 Unicode 排序而不是按出现顺序：这样它与年份范围无关，重新生成数据时
索引不会整体错位。冲那里存的是**地支**而不是生肖，生肖由 Dart 用固定的十二支
映射推出来——这样「冲 = 日支 + 6」这条不变量可以被测试直接验证。

### 生成时的自检

`tool/generate_huangli.py` 每次生成都会跑这三条不变量，不通过就拒绝出数据；
`test/huangli_test.dart` 在 Dart 侧对**全部 22281 天**再验证一遍：

- 日干支每天正好前进一位（六十甲子循环）
- 冲必须是日支的对面（相隔六位）
- 每一行的宜忌索引都能解析出词（没有越界被静默丢掉）

这些不需要第二个实现就能验证，而且是抓编码错误最有效的手段。

## 备份

日记是**唯一一份**，而且现在还会同步到手机——但**同步不是备份**：它会把误删和
误改一起复制到两台设备上。所以备份必须落在**第三个地方**。

### 怎么设

编辑区右下角**「更多」菜单 → 备份**：

| 项 | 说明 |
|---|---|
| 备份位置 | **必须你自己设**。没设之前「立即备份」是禁用的，旁边写着原因——不是藏起来 |
| 立即备份 | 可以填一句说明，会写进快照的目录名和清单里 |
| 从备份恢复 | 只恢复到**新文件夹**，绝不写回正在用的日记目录 |
| 打开备份文件夹 | 在资源管理器里定位 |

备份目录下是 `自动/` 和 `手动/` 两个子目录，每份快照里有一个 `备份清单.txt`
（时间、类型、来源、文件数、总字节，以及逐文件的路径 / 大小 / 修改时间）。
有了它，三年后打开一份快照，不依赖任何程序就能判断它是不是完整的。

**快照里进什么**：`2026/`（日记本体）、`.history/`（历史版本）、`.trash/`（回收站）。
**不进什么**：`.drafts/`、`*.tmp-*`、`.index.sqlite`、同步工具的标记目录。

> 注意这里和同步的忽略规则**方向相反**：`.history` 和 `.trash` 要**排除出同步**
> （每台设备各有一份，同步只会互相制造冲突），但**必须包含进备份**——
> 出错之后最想要的就是这些东西。

### 自动快照和手动快照

| | 什么时候做 | 保留 |
|---|---|---|
| **自动** | 关闭程序时。**一天至多一份**，而且内容没变就跳过 | 只保留最近 **30** 份 |
| **手动** | 你点「立即备份」 | **永不删除**（程序里没有任何代码路径会删它） |

那两道限制都是为了让「保留 30 份」真正等于"约一个月的写字日"：不加"一天至多一份"，
开关十次程序就产生十份，30 份只覆盖三天；不加"内容没变就跳过"，只是打开看看
也会留下一份完全一样的快照。

清理旧自动快照时，程序**只删自己建的那些**，而且删之前会确认目录里确实有
`备份清单.txt`——**一个认不出来的目录，宁可多占空间也绝不删**。手动快照所在的
`手动/` 目录，保留策略根本不会去看。

### 它挡得住什么、挡不住什么

| 备份位置 | 挡得住 | 挡不住 |
|---|---|---|
| 另一块盘 / 移动硬盘 | 误删、误改、单块盘坏掉 | 火灾、失窃这类"两台设备一起没" |
| **和日记同一个盘** | 误删、误改 | **这块盘坏掉** |

界面会把这件事如实说清楚：同盘时明确提示"挡不住这块盘坏掉"，并补一句
**两个盘符也可能是同一块物理盘**——这一点程序判断不了，所以只能提示、不能保证。
被拒的只有一种情况：备份位置和日记目录**互相包含**（会递归复制，而且会被
Syncthing 同步到手机）。

### ⚠️ 上传云盘的节奏 = 你的数据安全窗口

如果备份只落在电脑上的另一个文件夹，那么**真正防住盘坏的是"把备份传到云盘"
这一步**。程序看不见云盘，无法知道你什么时候传过，所以这个节奏只能你自己把握：

- 一个月传一次 → 盘坏时最多丢一个月
- 想省掉手动这一步：如果云盘客户端有本地同步文件夹（OneDrive、坚果云这类都有），
  直接把备份位置指向它。代价是你在本地删旧快照时，云端那份也会跟着删
  （有些客户端保留历史版本，有些不会）

## 更改日记位置

入口在编辑区右下角的**「更多」菜单 → 日记存储位置**。行为和安全保证：

| 保证 | 说明 |
|---|---|
| **只复制，从不移动** | 勾选复制后，原文件夹一个字节都不会被改动。确认新位置没问题后，删不删旧文件夹由你决定 |
| **拒绝覆盖** | 目标位置只要存在同名文件，复制立刻中止。所以「复制」在任何情况下都不会毁掉目标位置原有的内容 |
| **复制后逐个校验** | 比对每个文件的大小。校验不过就报错，且**设置不会被改动**——程序仍然指着原来的位置 |
| **切换前先落盘** | 正在写的那句话会先存回原位置，再开始复制，避免最后一段内容丢失 |
| **设置最后才写入** | 保证「设置」永远只描述一个确实可用的位置。任何一步失败，设置都不变 |

界面会实测而不是猜测：目标能不能写（真的建一个临时文件再删掉）、里面已经有几篇日记、
有没有别的 `.md` 文件、磁盘是可移动还是网络盘。

**已知的取舍**：没有调用系统原生文件夹选择器，因为那需要插件，而插件在 Windows 上要求
开启开发者模式。所以是「自己用 `dart:io` 列目录的内置选择器 + 手输路径」，
不如资源管理器顺手。

### Windows 桌面 App（目标形态）

需要 **Visual Studio C++ 生成工具**。这是 Flutter 编译 Windows 原生程序的硬性要求，
且安装需要管理员权限。在**管理员** PowerShell 里执行：

```powershell
winget install --id Microsoft.VisualStudio.2022.BuildTools --accept-package-agreements --accept-source-agreements --override "--quiet --wait --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
```

装完后：

```powershell
flutter doctor          # Visual Studio 那一项应该变成 [√]
flutter run -d windows
```

打包成可双击运行的程序：

```powershell
powershell -File tool\build_release.ps1
# 产物在 build\windows\x64\runner\Release\（exe + flutter_windows.dll + data\，共约 29MB）
```

> **不要直接用 `flutter build windows --release`。** 见下面「构建陷阱」——
> 增量构建会让新图标静默失效。脚本做的是 `clean` → 构建 → 审计三步。

### 构建陷阱：图标字体子集不会被增量重建

Flutter 打包时会把 `MaterialIcons-Regular.otf` 从 1.6MB 裁剪到只剩程序用到的字形
（本项目约 4.7KB）。但**这个裁剪结果在增量构建里不会重新生成**：

```
第一次完整构建   → 字体含当时用到的 22 个图标
之后新增 3 个图标 → 增量构建，字体仍是旧的 → 那 3 个图标在界面上是空白方框
```

构建**不会失败、不会报警告**，只是图标不见了。这个坑真实踩过：外观菜单的
三个图标（跟随系统/浅色/深色）全部不可见，而同一版本里其它 22 个图标完全正常。

两道防线：

```powershell
# 1. 用脚本构建（内部强制 clean）
powershell -File tool\build_release.ps1

# 2. 单独审计字体覆盖（会列出代码里用到但字体里没有的每一个图标）
python tool\icon_audit.py `
  D:\Dev\flutter\packages\flutter\lib\src\material\icons.dart `
  lib `
  build\windows\x64\runner\Release\data\flutter_assets\fonts\MaterialIcons-Regular.otf
```

审计输出必须是 `app icons MISSING : 0`。

**顺带一个已知的坑**：`Icons.info_outline` 和 `Icons.info_outlined` 这两个码点
即使在完整构建里也会被裁掉（用哪个变体都一样），是 Flutter 图标字体自身的缺口。
不要用它们；`tool/icon_audit.py` 能查出这类问题。

### 浏览器预览（只看界面，不能真正用）

```powershell
flutter run -d chrome
```

> **注意**：web 模式下数据存在内存里，**不会持久化**，刷新就没了。

## 测试

```powershell
flutter test        # 489 个测试
flutter analyze     # 静态检查
```

测试覆盖了真实文件系统语义，不只是内存桩：Windows 上 rename 能否覆盖已存在文件、
点目录是否被正确跳过（否则删掉的日记会"复活"）、非 UTF-8 文件是否会让整库读不出来、
连续输入时草稿节流是否真的生效、窄窗口下布局是否溢出、操作系统文件锁**跨进程**
是否真的能挡住第二个实例。

两条踩过的坑，写在测试文件开头防止以后改坏：

- **真实文件 I/O 必须用普通 `test()`，不能改成 `testWidgets()`。**
  `testWidgets` 跑在假异步环境里，`await` 真实 `dart:io` 的 Future **永远不会返回**，
  而且 `--timeout` 也拦不住。
- **界面测试里不能拿正文当定位文本。** 正文同时出现在列表预览和编辑框里，
  `find.textContaining` 会命中两处，`getCenter` 之类的定位就失效了。

## 数据在哪

默认：`%USERPROFILE%\Documents\riji`

```
riji/
├── 2026/
│   ├── 2026-02-14.md
│   └── 2026-02-15.md
├── .drafts/          # 本机草稿，不参与同步
├── .history/         # 历史快照，不参与同步
│   └── 2026-02-14/
│       ├── 213045123-opened.md
│       └── 220512004-auto.md
└── .trash/           # 软删除的内容，可手工恢复
```

以 `.` 开头的目录**都不会被当成日记读进来**——漏掉这条，用户删掉的日记
会在下次启动时"复活"。

程序设置（日记根目录、主题、字体）存在 `%APPDATA%\riji\settings.json`，
与日记数据分开；单实例锁在同目录的 `instance.lock`。

## 双端同步

**不要自己写同步服务。** 二选一：

- **Syncthing** —— 实时、免费、无云、端到端加密；手机端用 Syncthing-Fork。
- **私有 git 仓库** —— 多一层版本历史和后悔药，适合定时 commit。

同步的就是上面那个日记根目录。必须忽略：

```
.index.sqlite        （将来若引入索引）
.drafts/
.history/
.trash/
*.tmp-*
```

`.history/` 和 `.trash/` 也必须忽略：它们是**本机的操作痕迹**，同步它们只会
让两台设备互相制造冲突文件，白白把容量和噪音翻倍。（`DiaryPaths.syncIgnorePatterns`
里有完整列表。）

同一天在两台设备上都被改过时，同步工具会保留双方版本。程序会把冲突文件列出来让你手动合并，
**不会替你决定保留哪句话**。

## 几个刻意的取舍

**关于加密：程序不做加密，日记是明文。**
你明确选择了「不需要加密」。既然这是个清醒的决定，这里就不写任何暗示"有保护"的话：

- 日记以**明文**存放在磁盘上（`.md` 文件，`type` 一下就能看）
- 程序**不提供**任何加密、口令或访问控制
- 安全性完全取决于**你所在环境的访问控制**：谁能登录这台电脑、谁物理接触得到它、
  系统盘有没有开 BitLocker、备份和云盘上那份谁能看见

程序**没有权限查询 BitLocker 状态**（`Get-BitLockerVolume` 需要管理员），所以磁盘
到底有没有加密，程序不知道、也无法保证；想确认可以在管理员 PowerShell 里跑
`manage-bde -status`。更改日记位置时程序会提醒这一点。

**手机同步会引入两个额外的、程序无法验证的前提**：

1. **手机本身的存储加密状态**
2. **手机厂商的云备份范围** —— 如果它把 `Documents/` 一起备份上去，
   日记就去了一个"全盘加密"管不到的地方

这两条只能你自己在手机上确认，见 [`docs/手机写作.md`](docs/手机写作.md)。

**为什么一天一个文件，而不是一个数据库？**
文件粒度就是同步粒度，双端冲突面天然最小；纯文本几十年后依然能读；数据和程序解耦。
数据库只做索引和缓存，不是唯一真相来源。

**为什么不引入 SQLite？**
数据量小到可以忽略：一年 365 个文件，写十年也才 3650 个，全量扫描就是毫秒级。
少一个依赖就少一处会坏的地方。真到了需要索引的那天再加，索引是可再生的。

**为什么零插件（连 `path_provider` 都不用）？**
Flutter 为插件建符号链接要求 Windows 开启开发者模式，而开开发者模式需要管理员权限。
只为定位一个默认目录付这个代价不值得——用环境变量就够了。

**为什么深色模式几乎没改组件代码？**
因为界面里所有颜色从一开始就走 `theme.colorScheme.*` 令牌，全项目只在
[`lib/ui/theme.dart`](lib/ui/theme.dart) 里硬编码了 1 个种子色（其余 30 处全是令牌引用）。
换一个 `ColorScheme`，所有组件自动跟着变。这不是运气，是「不写死颜色」这条纪律的直接回报——
如果当初随手写了 `Colors.grey`，现在就要逐个组件去改，还一定会漏。

**为什么正文用 TextField 而不是富文本编辑器？**
日记的价值在内容不在排版。所见即所得编辑器会带来格式转换、粘贴污染、
导出失真一整类问题，而收益接近于零。Markdown 源码本身就是最好的格式。
